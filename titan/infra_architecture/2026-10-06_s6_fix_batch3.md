### A1. 탐지 view×proj 행렬 — 스캔당 1회 (감사 §3-2) [A] 적용

- **무엇**: `Detection/TargetDetectionComponent.cpp` `ScanTargets` ~165-190 — 스캔 시작에 `BuildCameraViewProjection(Camera, ResolveAspectRatio(), ScanViewProjection)` 1회, 대상마다 `EvaluateTarget(AActor*, const FMatrix* ViewProjection)`(~285)로 넘김. 코너 8개는 `ProjectWithViewProjection(*ViewProjection, WorldCorner, UV)`(~344).
- 예전: 코너마다 `ProjectToScreenUV` → `ProjectWorldPointToCameraUV`가 **같은 카메라·같은 화면비로 같은 행렬을 다시** 구성(대상 × 8회/스캔).
- **결과 동일 근거**: `ProjectWorldPointToCameraUV`(~569-575, RCWS 조준점 UI 마커가 쓰는 public static)는 이제 `BuildCameraViewProjection`(~577) + `ProjectWithViewProjection`(~607) 그 자체 → 두 경로 모두 같은 `(ViewMatrix * ProjectionMatrix).TransformFVector4(...)` 산술, **비트 동일**.
- 헤더(`TargetDetectionComponent.h` ~226-259): public static `BuildCameraViewProjection` / `ProjectWithViewProjection` 신설, private `EvaluateTarget` 시그니처 변경(리플렉션 없음). `ProjectToScreenUV` 멤버는 이제 미사용이지만 남겨 둠.
- **안 한 것(지시대로)**: 대상마다 `CalcBounds` 대신 캐시된 `Bounds` 사용 · 결과를 안 읽는 프로세스의 넷모드 게이트 — 둘 다 판정 입력/실행 여부가 바뀔 수 있어 범위 밖.

### A3. 시나리오 로그 — 줄마다 디스크 싱크 → 주기 싱크 (감사 §3-8) [A] 적용

- **무엇**: `UI/ScenarioMonitorSubsystem.h/.cpp` — writer를 `TUniquePtr<FArchive>`(`CreateFileWriter`)에서 **`TUniquePtr<IFileHandle>`** 로(`.h` ~124-132). 열기는 `FPlatformFileManager::Get().GetPlatformFile().OpenWrite(path, bAppend=false, bAllowRead=true)`(`.cpp` ~294-297) — `CreateFileWriter`가 내부에서 하는 바로 그 호출(엔진 `Core/Private/HAL/FileManagerGeneric.cpp:110`)에서 FArchive 버퍼만 빠진 것.
- **줄마다**: `IFileHandle::Write` = Windows `WriteFile` 완료(`WindowsPlatformFile.cpp:878-930`) / Linux `write()`(`UnixPlatformFile.cpp:303-321`) → OS 캐시에 들어감 → **프로세스 크래시에도 남는다**.
- **디스크 싱크**(`IFileHandle::Flush` → Windows `FlushFileBuffers`, `bFullFlush` 무시 `WindowsPlatformFile.cpp:933-937` / Linux `fdatasync` `UnixPlatformFile.cpp:323-328`)는 `SyncLogFiles(bForce)`(~313-337)만 한다:
  - **강제**: FAIL 카테고리 줄(~354) · `WriteWorldSnapshot` 끝 "---- 스냅샷 끝 ----"(~846) · `cycles.csv` 행마다(`WriteCycleRow`, 클라·서버 ~415·~440) · `Deinitialize`(세션 끝 ~214).
  - **그 외**: 새 cvar **`titan.ScenarioLog.DiskSyncSeconds`**(기본 2.0, **0 = 줄마다 싱크 = 예전 거동**) 간격이 지났고 밀린 줄이 있을 때만. 줄마다와 매 `Tick`(~241)에서 확인.
- 예전 FArchive 경로: `Serialize`가 `BufferArray`에 모으고 `Flush` = `FlushBuffer` + `Handle->Flush`(`FileManagerGeneric.cpp:970-1021`) → 결국 줄마다 OS 싱크였다.
- **쓰는 바이트는 동일**(같은 BOM, 같은 UTF-8 줄). 스냅샷 1회 ≈45 싱크/프레임 → **1~2회**.
- **잔여 위험**: OS 크래시·전원 차단이면 최대 `DiskSyncSeconds`만큼의 줄을 잃을 수 있다(프로세스 크래시는 아님).
- **안 바꾼 것**: `Diagnostics` 블랙박스 `TitanHealthRecorderSubsystem.cpp` ~332도 줄마다 flush("이벤트는 드물다" 주석) — 범위 밖, 후보로만.
