# 병사 애니메이션 가이드 — 디자인팀용 (초안)

2026-09-14 / **초안 (조작법 확정 — 조준·사격·재장전 키만 확인 필요)** / 새 병사 시스템의 이동·자세 기능 하나하나에 어떤 애님 시퀀스가 짝지어져 있는지, 어떤 것은 시퀀스로 못 고치는지, 어떻게 실행해 보는지를 디자이너 기준으로 정리.

> 내부 배선 상세는 `2026-09-14_design_team_animation_handoff.md`(같은 폴더)와 `IMPLEMENTED.md` 2절에 있다. 이 문서는 디자이너에게 **그대로 전달하는 문서**이므로 내부 용어를 최소화한다.

---

## 0. 한 장 요약

- 병사는 **모션 매칭(Motion Matching)** 으로 움직인다. 이동 클립 61개 중에서 매 순간 가장 잘 맞는 프레임을 골라 붙이므로, **클립 하나를 고치면 그 클립이 골라지는 순간의 모습이 바뀐다.** "이 상황엔 이 클립"이 고정돼 있지 않다.
- 조준·총내림·기울이기·맹목사격·앉기 같은 **자세**는 이동 클립 **위에 얹힌다.** 얹히는 재료 중 시퀀스인 것(고칠 수 있음)과 코드가 본을 직접 돌리는 것(고칠 수 없음)을 1절에서 기능마다 나눠 적었다.
- 왼손 IK는 **기본 꺼져 있다.** 왼손이 총열에 붙는 것은 이제 시퀀스가 책임진다.
- 모든 클립은 `/Game/SoldierLab/Animations/` 아래, 스켈레톤은 `SK_UEFN_Mannequin`. **이름·경로를 바꾸지 말고 리임포트로 덮어쓴다.**

## 1. 기능 ↔ 애님 시퀀스

### 1.1 서서 이동 (걷기 · 조깅)

| 상황 | 클립 (`Animations/Rifle/`) | 수 |
|---|---|---|
| 제자리 (견착) | `Idles/MM_Rifle_Idle_ADS` | 1 |
| 제자리 (총내림) | `Idles/MM_Rifle_Idle_Hipfire` · `MM_Rifle_IdleBreak_Fidget` · `MM_Rifle_IdleBreak_Scan` | 3 |
| 제자리 회전 | `TurnInPlace/MM_Rifle_Turn{Left,Right}_{90,180}` | 4 |
| 걷기 루프 | `Loops/MM_Rifle_Walk_{Fwd,Bwd,Left,Right}` | 4 |
| 걷기 출발 / 정지 / 방향전환 | `Starts/…_Start` · `Stops/…_Stop` · `Pivots/…_Pivot` (각 4방향) | 12 |
| 조깅 루프 | `Loops/MM_Rifle_Jog_{Fwd,Bwd,Left,Right}` | 4 |
| 조깅 출발 / 정지 / 방향전환 | `Starts/…` · `Stops/…` · `Pivots/…` | 12 |

- 대각선 이동 클립은 **없다.** 4방향 클립을 코드가 비틀어(워핑) 만든다 — 대각선에서 발이 가끔 꼬이는 원인.
- **이동 속도는 클립에서 실측한 값**이다: 걷기 291.31 · 조깅 582.62 cm/s, 4방향 모두 같다. 클립 속도를 바꾸면 알려줄 것 — 코드의 속도 설정을 같이 맞춰야 한다. 안 맞으면 걸을 때마다 출발/정지 클립이 잘못 골라져 **떨린다.**
- 총을 내린 채 이동하는 클립은 **없다** (→ 1.4).

### 1.2 앉아서 이동

| 상황 | 클립 | 수 |
|---|---|---|
| 앉은 제자리 | `Idles/MM_Rifle_Crouch_Idle` | 1 |
| 앉은 제자리 회전 | `TurnInPlace/MM_Rifle_Crouch_Turn{Left,Right}_{90,180}` | 4 |
| 앉은 걷기 루프 / 출발 / 정지 / 방향전환 | `Loops/MM_Rifle_Crouch_Walk_{…}` · `Starts/…` · `Stops/…` · `Pivots/…` | 16 |

- 앉아서 뛰는 클립은 **없다.** 앉으면 속도가 걷기로 묶인다.
- **서기 ↔ 앉기 사이의 중간 높이는 클립이 아니다.** 코드가 골반을 내리고 무릎을 굽힌다(→ 2절 ②). 완전히 선 상태와 완전히 앉은 상태에서만 클립이 100% 보인다.

### 1.3 조준 (견착)

| 재료 | 에셋 | 비고 |
|---|---|---|
| 서서 조준 방향 15장 | `Rifle/Poses/MM_Rifle_Idle_ADS_AO_{CC,CU,CD,LC,LU,LD,RC,RU,RD,LBC,LBU,LBD,RBC,RBU,RBD}` | `Rifle/AO_Rifle_ADS` 로 묶임 |
| 앉아 조준 방향 15장 | `Rifle/Poses/MM_Rifle_Crouch_Idle_AO_{…}` | `Rifle/AO_Rifle_Crouch` |

- 이름: C/L/R/LB/RB = 좌우 0 / −90 / +90 / −180 / +180°, C/U/D = 상하 0 / 위 / 아래.
- 각 포즈는 **"기준 클립 프레임 0 과의 차이"** 로 저장돼 있다(애디티브). 기준은 `MM_Rifle_Idle_ADS` / `MM_Rifle_Crouch_Idle` 의 **프레임 0**. → **기준 idle 의 첫 프레임을 고치면 조준 포즈 15장이 전부 같이 움직인다.** 둘을 같이 볼 것.
- 이 포즈들의 정확도가 곧 총구 방향이다. 상하 표본이 3장뿐이라 총구가 조준선에서 약간 벗어나고, 그것을 코드가 보정한다(→ 2절 ④). **포즈를 정확히 고치면 보정량이 자동으로 줄어든다.**

### 1.4 총내림 (로우레디) ★

전용 클립이 **없다.** 두 가지의 합성이다:

| 상황 | 무엇이 보이나 | 고칠 수 있는 시퀀스 |
|---|---|---|
| 제자리 | `MM_Rifle_Idle_Hipfire` (+IdleBreak 2장) 위에 "정면·완전 아래" 조준 델타를 얹음 | `Idles/MM_Rifle_Idle_Hipfire` · `IdleBreak_*` · `Poses/MM_Rifle_Idle_Hipfire_AO_CD` / `_CC`(델타의 양 끝) |
| 이동 중 | 견착 이동 클립(1.1) 위에 **같은 델타**를 얹음 | 델타 두 장만. 이동 클립 자체를 총내림용으로 고치면 견착 이동이 같이 바뀐다 |

- 델타 = `MM_Rifle_Idle_Hipfire_AO_CD − MM_Rifle_Idle_Hipfire_AO_CC`. 어깨를 내리는 회전이 전부라 어떤 이동 클립 위에도 자연스럽게 얹힌다.
- **총내림 전용 포즈 한 장을 저작해 얹는 방식은 두 번 시도해서 두 번 실패했다**(2026-09-13 · 09-14) — 정지에선 되는데 이동 중 팔꿈치가 몸 안으로 들어간다. 팔꿈치·손을 바꾸는 큰 델타는 걷기 클립 위에서 축이 안 맞는다. **디자이너가 총내림 포즈를 새로 만들어 주셔도 같은 이유로 이동 중엔 못 쓴다.**
- 제대로 하려면 **총 내린 채 이동하는 클립 세트**(최소 Walk/Jog 루프 4방향 = 8장, 제대로는 출발/정지/방향전환까지 32장)가 필요하다. 요청 시점은 추후.
- 총을 내리는 **판정**(조준각이 70°를 넘으면 내린다, 내릴 때 0.125초 / 올릴 때 0.5초)은 코드다.

### 1.5 맹목사격 (블라인드 파이어)

| 포즈 | 에셋 | 기준 |
|---|---|---|
| 왼쪽으로 총 내밀기 | `Rifle/Poses/MM_Rifle_BlindFire_L` | `MM_Rifle_Idle_ADS` 프레임 0 |
| 오른쪽 | `…_BlindFire_R` | 동 |
| 위로 (담 너머) | `…_BlindFire_U` | 동 |

- 150프레임짜리 파일이지만 **프레임 0 만 쓴다.** 프레임 0 에만 키를 찍을 것.
- 상체(척추·팔·목·머리)만 얹히고 다리는 이동 클립 그대로.
- 기준이 `MM_Rifle_Idle_ADS` 프레임 0 이므로 **ADS idle 을 고치면 이 3장도 같이 틀어진다.**

### 1.6 사격 · 재장전

| 동작 | 몽타주 | 클립 | 비고 |
|---|---|---|---|
| 사격 (반동) | `Actions/AM_MM_Rifle_Fire` | `Actions/MM_Rifle_Fire` (애디티브, 기준 `Actions/MM_Rifle_Idle_Hipfire`) | 탄이 실제로 나갈 때만 재생 |
| 재장전 | `Actions/AM_MM_Rifle_Reload` | `Actions/MM_Rifle_Reload` + `MM_Rifle_Reload_Additive` | 상체만. 재생 중 조준 오프셋이 꺼진다 |

- ⚠ `Actions/MM_Rifle_Idle_ADS` · `Actions/MM_Rifle_Idle_Hipfire` 는 `Rifle/Idles/` 의 같은 이름과 **다른 파일**이다(반동 기준용). 헷갈리지 말 것.
- 재장전 클립의 `DisableLHandIK` 커브가 왼손 IK 를 끄는 신호다 — 지금은 IK 자체가 꺼져 있어 무관하지만 커브는 지울 것 없이 두면 된다.

### 1.7 좌우 기울이기 (린)

**시퀀스 없음.** 코드가 척추 5마디를 직접 기울인다. 이동 중 몸이 자연스럽게 기우는 것(뱅킹)은 별도 — GASP 원본 `BS1D_Additive_Lean_Run` 이고 건드리지 않는다.

### 1.8 반입만 되고 아직 안 쓰는 것

`Actions/` 의 피격 13장(`MM_HitReact_*`) · 사망 6장(`MM_Death_*`) · 대시 · 장착/해제 · 근접 · 수류탄 · 권총/샷건 계열, `Rifle/_Extra/` 12장(점프 · 앉기 전환 · 린 클립), `Rifle/AO_Rifle_Aim`, `Rifle/Poses/MM_Rifle_LowReady` · `*_OverridePose` · `MM_Rifle_Idle_Hipfire_AO_*` 나머지 13장. **고쳐도 화면에 안 나온다.** 피격/사망은 곧 배선 예정 — 그때 목록을 갱신한다.

## 2. 시퀀스로 못 고치는 것 (코드가 본을 직접 움직이는 층)

이것들은 시퀀스 위에 **항상** 얹힌다. 문제가 여기서 보이면 우리에게 알려 달라.

| # | 무엇 | 어떻게 | 언제 0 이 되나 |
|---|---|---|---|
| ① | 좌우 기울이기 | 척추 5마디 회전 | 기울이기 키를 안 누를 때 |
| ② | 서기↔앉기 중간 높이 | 골반을 내리고 무릎을 굽힘 | 완전히 섰을 때 / 완전히 앉았을 때 |
| ③ | 조준 방향 적용 | 1.3 의 포즈를 조준 각도만큼 섞음 | 정면·수평 조준 |
| ④ | 총구 보정 | 총구가 조준선에서 벗어난 만큼(±25° 이내) 조준 각도를 되먹임 | 1.3 포즈가 정확할수록 |
| ⑤ | 총내림 합성 | 1.4 의 델타를 마스크로 얹음 | 견착 중 |
| ⑥ | 맹목사격 적용 | 1.5 의 포즈를 상체 마스크로 얹음 | 맹목사격 키를 안 누를 때 |
| ⑦ | 왼손 IK | 왼손을 총 그립에 끌어당김 | **지금 기본 OFF.** 켜려면 ABP `LeftHandIKEnabled` |
| ⑧ | 발 접지 · 보폭/방향 워핑 · 몸통 지연 | GASP 기본 기능. 클립 속도와 실제 속도 차이를 다리 변형으로 흡수 | 클립 속도 = 코드 속도일 때 최소 |
| ⑨ | 머리 조준 추종 (**기본 꺼짐**, H) | 켜면 머리가 **항상** 마우스(조준) 쪽을 본다 — 시퀀스의 머리 회전 위에 차이만 **더하므로** 빠른 흔들림·롤(기울이기)은 그대로 남고, 오래 유지되는 포즈는 조준 쪽으로 당겨진다. **견착 중** 총이 조준선에 올라오는 동안 그에 맞춰 목 두 마디를 굽히고(최대 60°) 머리를 살짝 밀어(최대 5 cm) **눈을 조준경 뒤 조준선 위에** 올린다; 붙은 뒤 급선회·반동으로 총이 잠깐 벗어나도 0.5 초는 붙어 있다. **맹목사격 중엔 통째로 꺼진다**(시퀀스의 고개 돌림이 그대로). **비조준으로 가만히 서서** 마우스를 60° 넘게 돌리면 몸(캡슐)이 따라 돌고 GASP 의 제자리 돌기(turn-in-place)가 나온다 — 시퀀스는 조준 모드와 같은 것을 쓴다(`SoldierLab \| HeadAim \| BodyTurn`, 이동 중엔 안 돎). 값 전부 `BP_SoldierCharacter` → `AC_SoldierHeadAim` Details (`SoldierLab \| HeadAim \| …`) | **기본(꺼짐)** · 맹목사격 · 총내림·달리기(눈 정렬만 풀림, 시선은 계속) |

**검수 요령**: 시퀀스가 그대로 보이는 조건은 **제자리 · 정면 조준(또는 총내림 정지) · 축 전부 0 · IK OFF · 머리 추종 OFF(H)** 다. 그 상태에서 먼저 보고, 키 하나씩 눌러 가며 ①~⑥ 이 얹힌 모습을 따로 본다.

## 3. 수정 규칙

1. **이름·경로·파일을 바꾸지 않는다.** 리임포트로 덮어쓴다. 새 파일을 만들면 어디에도 안 걸린다.
2. 루프 클립은 첫·끝 프레임이 이어져야 한다. 루트 본은 잠근다(`Force Root Lock` 켜짐 유지).
3. **커브를 잃지 않는다.** 리임포트 후 각 클립의 Animation Modifiers 를 **목록 순서대로 Apply All.** `contact_l/r`(발 접지) · `enable_warping` · `Phase` · `DisableLHandIK` 가 클립 안에 산다. 없으면 발이 조용히 미끄러진다.
4. 1.3 · 1.4 · 1.5 의 **기준 프레임 0 종속**을 기억한다 — 기준을 고치면 딸린 포즈를 같이 확인.
5. 1프레임 포즈(1.3 · 1.4 델타 · 1.5)는 **프레임 0 에만** 키를 찍는다.
6. 포즈를 새로 만들거나 베이크할 땐 **마네킹 메시**(`SKM_UEFN_Mannequin`)로 한다. 병사 메시로 베이크하면 척추 간격이 틀어진 클립이 나온다.
7. 이동 클립에서 클립을 **추가·삭제하거나 속도를 바꿀 땐 먼저 말한다.**
8. 스켈레톤(`SK_UEFN_Mannequin`)에 본을 추가하지 않는다.

## 4. 실행해 보는 법

### 4.1 기본

```
레벨       /Game/SoldierLab/Levels/L_SoldierTest
게임모드    GM_SoldierLab   (World Settings → GameMode Override 또는 PIE 설정)
```

PIE 를 켜면 플레이어 병사 하나가 스폰되고 아군(`Ally_*`)·적군(`Enemy_*`)이 AI 로 교전한다.

### 4.2 누구로 들어갈지 고르기 — `GM_SoldierLab` 의 `Default Pawn Class`

| 폰 | 무엇 | 용도 |
|---|---|---|
| `BP_ObserverPawn` | 자유 시점 관전 (`GM_SoldierObserver` — `L_SoldierTest` 의 기본) | AI 끼리 싸우는 것을 본다. 병사를 **따라다니기(F)** — 병사는 AI 그대로 움직인다 |
| `BP_Soldier_Friendly` | 아군 병사 (soldier_T 외형) | 직접 조작해 클립 검수 |
| `BP_Soldier_Hostile` | 적군 병사 (enemy_T 외형) | 동. 아군 AI 가 나를 쏜다 |

- ⚠ `GM_SoldierLab` 의 **`Pawn Classes Soft` 배열이 비어 있어야** `Default Pawn Class` 가 쓰인다(배열에 뭐가 있으면 그 0번이 스폰된다 — 2026-09-14 확인).
- 아군/적군은 **같은 블루프린트(`BP_SoldierCharacter`)의 자식**이라 조작·애니메이션이 동일하고 진영과 외형만 다르다.

- V/B · Q/E · 1~4 는 **누르는 동안 등속으로 올라가고, 떼면 그 값에서 멈춘다.** 0 으로 돌아가지 않는다(맹목사격은 4 로 해제).
- ⚠ 기존 앉기 토글(C)은 **동작하지 않는다.** V/B 만 쓴다.
- 1인칭은 카메라가 머리의 `eyes` 소켓에 붙는다. 머리 추종(H)을 켜면 머리 움직임(기울이기·흔들림)이 시야에 그대로 나오고, 견착 후 총이 조준선에 올라오면 눈이 조준경 뒤 조준선 위로 옮겨간다(목을 굽힌다). 머리 추종이 꺼져 있으면 마우스가 시야를 직접 잡는다.
- 관전 폰의 F 판정 각도(`Pick Cone Degrees`, 기본 15°)와 두 컴포넌트의 키·문턱값은 전부 블루프린트 Details 에서 바꿀 수 있다.

## 5. 문의 / 보고 형식

문제를 보고할 때 다음 넷을 적어 주면 바로 짚을 수 있다:

1. **어느 폰**으로 (관전 / 아군 / 적군)
2. **어떤 키 상태**에서 (조준 여부 · V/B · Q/E · 1~4)
3. **정지인지 이동 중인지**, 이동이면 방향
4. 화면 캡처 또는 영상 (`slomo 0.1` 이면 더 좋다)

"클립 X 를 고쳤는데 안 바뀐다" 는 대개 ① 그 클립이 골라지지 않는 상황이거나 ② 2절의 층이 위에 얹혀 있는 경우다 — 위 정보가 있으면 어느 쪽인지 바로 갈린다.
