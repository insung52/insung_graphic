## 2. IK Rig 감사 결과 — **수정할 것 없음** [A]

### 2.1 IK Goal은 소스 리그에서 쓰이지 않는다

체인마다 IK Goal이 채워지거나 `None`이거나 제각각인데 **상관없다.** 엔진에서 `IKGoalName`을
소비하는 지점을 전수 조사한 결과 **전부 타깃 체인에서만** 읽는다:

```
IKRetargeter.cpp:282     TargetIKRigAsset->GetRetargetChains() → if (Chain.IKGoalName != NAME_None)
IKChainsOp.cpp:320       IKChain.GetTargetChain().IKGoalName
IKRetargetOpUtils.h:74   TargetChains 루프 → if (TargetChain.IKGoalName == NAME_None)
StrideWarpingOp.cpp:144  TargetBoneChain->IKGoalName
```

`GetSourceChain().IKGoalName`을 읽는 코드는 **한 군데도 없다.**

### 2.2 솔버가 없는 것도 정상이다

`ApplyAutoGeneratedRetargetDefinition()`은 `SetRetargetDefinition()`만 호출한다
(`IKRigController.cpp:492`). FBIK 셋업은 `ApplyAutoFBIK()`라는 **별개 함수**다.
즉 auto generate는 **체인·Pelvis·Root만 쓰고 솔버는 만들지 않는다.** 소스 리그에는 솔버가 필요없다.

### 2.3 ★ `Root Motion: Hips` 는 지우면 안 된다

auto generate가 `Root Motion`에 `Hips`를 채우는데, **이게 맞다.** 처음에 "비워야 한다"고
판단했으나 틀렸다.

```cpp
// RootMotionGeneratorOp.cpp
:89   SourceRootIndex = SourceSkeleton.BoneNames.Find(Settings.SourceRoot.BoneName);
:91   if (SourceRootIndex == INDEX_NONE) {
:93       Log.LogWarning("Root Motion Remap Op, missing source root bone {0}.");
:95       bHasAllPrerequisites = false;     // op 초기화 실패
:204  Settings.SourceRoot = SourceIKRig->GetRoot();   // IK Rig에서 자동 시딩
```

**`SourceRoot`는 모드와 무관하게 유효한 본으로 해석돼야 초기화된다.** 비우면 op이 죽는다.
그래서 UI에도 `None` 선택지가 없고, `ClearPelvis` 명령은 있어도 `ClearRootMotion`은 없다.

런타임에서 `SourceRoot`가 실제로 쓰이는 건 `CopyFromSourceRoot` 모드뿐이다(`:143-150`).
**`GenerateFromTargetPelvis`로 두면 `Hips`가 들어있어도 무시된다.**

### 2.4 그 외 확인 항목

| 항목 | 판정 |
|---|---|
| `Pelvis: Hips` | ✅ |
| `Spine` 3본(Spine→Spine2) vs 타깃 5본(spine_01~05) | ✅ 리타기터가 정규화 분배 |
| 다리가 `LeftLeg`(UpLeg→Foot) + `LeftFoot`(ToeBase) 2체인 | ✅ Epic 표준 |
| 손가락 10체인 | ✅ |

## 3. ★ 리타기터가 루트모션을 만들 수 있다 — 파이프라인 [3]단계 재검토

`FIKRetargetRootMotionOpSettings` (`RootMotionGeneratorOp.h:29-77`):

```cpp
enum class ERootMotionSource {
    CopyFromSourceRoot,        // 소스 루트에서 복사 (기본값)
    GenerateFromTargetPelvis,  // ★ 리타깃된 Pelvis 모션으로 루트모션 생성
};
enum class ERootMotionHeightSource {
    CopyHeightFromSource,
    SnapToGround,              // 루트를 Z=0 으로
};
bool bRotateWithPelvis = false;        // ★ 기본 false
bool bMaintainOffsetFromPelvis = true;
bool bPropagateToNonRetargetedChildren = true;
```

`GenerateFromTargetPelvis`는 **`EncodeRootBoneModifier`가 하려던 일을 리타깃 시점에** 한다.
루트모션 op은 새 리타기터에 **자동으로 스택에 추가**된다(`IKRetargeterController.cpp:394`).

### 3.1 그런데 회전이 문제다 **[C-30]**

`bRotateWithPelvis`가 **기본 false**다. 이러면 루트가 회전하지 않고 방향 변화가 전부 몸에 남는다.
그러면 **`AM_WarpingAlpha`가 루트 회전 오차를 0으로 읽어 전 구간 "직선"으로 판정** →
`Enable_Warping`이 전부 1. **[C-27]과 같은 고장이 다른 경로로 재현된다.**

Epic도 `bRotateWithPelvis = true`에 대해 "Pelvis Yaw가 애니메이션되면 원치 않는 회전이
생길 수 있다"고 주석에 경고를 달아놨다(`:55`).

반면 `EncodeRootBoneModifier`는 `WeightedBoneToComputeRootOrientation`으로 여러 본의 축을
가중평균해 헤딩을 만든다(`EncodeRootBoneModifier.cpp:92-111`). **회전 안정성은 구조적으로 이쪽이 낫다.**

### 3.2 결론 — 둘 다 살려둔다

| | A: 리타깃 op | B: EncodeRootBone 모디파이어 |
|---|---|---|
| 이동 | `GenerateFromTargetPelvis` + `SnapToGround` | 발/골반 가중평균 |
| 회전 | `bRotateWithPelvis` — 불안 | 본 축 가중평균 — 우위 |
| 비용 | 리타깃에 포함, 일괄 처리 시 공짜 | 별도 모디파이어 패스 |

**직선 walk 하나로는 회전 차이가 안 드러난다.** 판정은 turn/pivot 클립을 받은 뒤로 미룬다.
지금은 **A로 통과시키고 B를 예비로 남긴다.**

## 4. ★ 진짜 위험 — 리타깃 포즈(T-pose vs A-pose)

Mixamo는 T-포즈, UE5 Manny는 A-포즈다. 안 맞으면 팔이 벌어지거나 어깨가 뒤틀린 채로
**전 클립이 구워진다.** `assets/...` 4.3절이 "골반 배치 문제"로 적어둔 항목의 실제 정체다.

**IK Rig이 아니라 리타기터에서 잡는다.** 엔진에 전용 기능이 있다
(`IKRetargetCommands.cpp` — 문구는 소스 확인값):

```
"Edit Retarget Pose"          수동 편집 모드 진입
"Show Retarget Pose"          리타깃 포즈 표시
"Align All Bones"             리타깃 포즈를 리셋하고 모든 리타깃 본을 자동 정렬
"Align Selected"              선택 본만
"Snap Character to Ground"    스켈레톤을 수직 이동해 원래 높이 복원
```

정렬 방식(`ERetargetAutoAlignMethod`, `IKRetargeterPoseGenerator.h:29`):

| 값 | 설명 |
|---|---|
| **`ChainToChain`** | 체인 방향으로 정렬 — **기본값이자 권장** |
| `MeshToMesh` | 스킨된 메시의 방향을 사용 |
| `LocalRotationAxes` / `GlobalRotationAxes` | 본 축 매칭. **두 캐릭터의 축이 다르면 심하게 틀어진다**(엔진 주석) |

## 6. 실제 실행 결과 (2026-09-03)

### 6.1 함정 — 새 리타기터는 **op 스택이 비어 있다**

에디터에서 IK Retargeter를 직접 만들면 **op이 하나도 없다.** 소스/타깃 IK Rig을 지정해도
자동 생성되지 않는다. `AddDefaultOps()`가 호출되는 건 `Export Selected Animations` 배치 창
경로뿐이다(`SRetargetAnimAssetsWindow.cpp:687`).

**이 상태에서는 Auto Align이 동작하지 않는다.** 같은 파일의 주석이 이유를 말한다:

```
// clear the op stack and add default ops
// NOTE: this must be done BEFORE generating the retarget pose
//       since it relies on the first op chain mapping
```

`ChainToChain` 정렬은 `GetChainTangent()`로 체인 방향 벡터를 구하는데
(`IKRetargeterPoseGenerator.cpp:143-144`), 그 체인 매핑을 **FK Chains op**이 들고 있다.
op이 없으면 기준 벡터가 없어 **팔이 T자 그대로 남는다.**

**해결**: `Op Stack` 탭의 **`Add Default Ops`** 버튼(`SRetargetOpStack.cpp:1102`).
툴팁: *"Add Pelvis Motion, IK/FK Chains and Root Motion Ops. Runs auto-setup on each op."*

### 6.2 UI 용어 (실물 확인)

| 문서/소스 용어 | 실제 UI |
|---|---|
| `Retarget Root` | **`Pelvis`** (IK Rig). 우클릭 `Set Pelvis` 또는 상단 `Pelvis:` 드롭다운 |
| `ChainToChain` | Auto Align 방식 드롭다운의 **`Default`** |
| Auto Align / Align All Bones | 툴바가 아니라 **`Hierarchy` 패널**의 `Auto Align ▼` |
| Root Motion op 설정 | **`Op Stack` 탭** → op 선택 → 오른쪽 Details |
| "Retarget Animations" | 좌하단 **`Asset Browser`** 탭 → **`Export Selected Animations`** |

### 6.3 `EncodeRootBone` 설정 — 실제로 쓴 값

MCP로 생성했다(`BlueprintTools.create` + `ObjectTools.set_properties`):

```
/Game/SoldierLab/AnimModifiers/AM_EncodeRootBone   (부모: EncodeRootBoneModifier)
  WeightedBoneToComputeRootPosition    : [ pelvis, weight 1.0 ]
  WeightedBoneToComputeRootOrientation : []          ← 의도적으로 비움
```

**회전을 비운 이유**: 가중치 합이 0이면 회전 블록을 건너뛴다(`.cpp:89`). 직선 walk에는 충분하고,
무엇보다 **본의 전방 축을 추측하지 않아도 된다** — `Yaw = Atan2(-Heading.X, Heading.Y)`(`.cpp:109`)라
축을 잘못 고르면 캐릭터가 옆을 보고 걷는다. turn/pivot 클립을 받으면 실측해서 채운다. **[C-31]**

Z는 원래 루트 값을 유지하므로(`.cpp:85`) 루트는 Z=0에 남는다.
