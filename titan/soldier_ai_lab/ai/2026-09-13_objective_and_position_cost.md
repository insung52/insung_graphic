## 0. 한 장 요약

```
Cost(자리) =        Exposure(도착지)               ← 거기 서면 드러나는가
                   (→ 09-14: FightingCost — 숨을 수 + 쏴 수 있는가)
          + RouteRiskWeight  × RouteRisk           ← 거기 가는 동안 드러나는가
          + ObjectiveWeight  × ObjectiveCost       ← 그 땅이 값이 있는가
```

**세 항 전부 0..1 한 통화다.** 통화가 같아야 가중치가 뜻을 갖는다.

| 무엇 | 어디 | 상태 |
|---|---|---|
| `ASoldierObjective` — 레벨 마커, 로직 없음 | `AI/SoldierObjective.h/.cpp` | [A] |
| 세 비용 스코어러 | `USoldierCoverComponent::ScorePosition` | [A] |
| 경로 노출 표본 | `USoldierCoverComponent::EvaluateRoute` | [A] |
| 레벨 배치 | **0개** | **[W25]** |
| 플레이에서의 거동 | **관찰하지 않았다** | **[C-88]** |

## 1. ★ 왜 이 층이 생겼는가 — **무모함은 용기가 아니라 값이 안 매겨진 항이다** (P72)

엄폐 층이 **노출만** 최소화할 때 병사들은 **무모하게 앞으로 기어 나갔다.** 용감해서가 아니다.

**노출을 낮추는 가장 싼 방법은 언제나 "제일 가까운 것 뒤로 한 발 더 들어가는 것"** 이고,
그 한 발이 어디를 향하는지는 아무도 말해 주지 않았다. 내주는 땅에도, 뺏는 땅에도 **값이
0으로 매겨져 있었으므로** 최적화기는 그것을 **없는 것으로 취급했다.**

> **최적화기가 비용 항을 하나만 가지면, 빠진 항은 사라지는 것이 아니라 *거동으로* 드러난다.**
> 이 층은 "돌격하라"는 규칙을 넣은 것이 아니라 **빠져 있던 항에 값을 매긴 것**이다.

## 2. 세 개의 비용, 하나의 통화 [A]

```cpp
return PositionExposure
     + RouteRiskWeight * RouteRisk
     + ObjectiveWeight * ObjectiveCost;
```

### 2.1 도착지의 노출

`..._engagement_and_cover.md` 7.2절 그대로다 — 몸을 따라 내려가며 트레이스해서
**처음 막히는 높이**를 찾고, 그것이 `Exposure` 이자 `RequiredStance` 다.

### 2.2 ★ 경로의 노출 — **서 있는 높이로 잰다** (P74)

```cpp
const float Alpha = (i + 1) / (RouteSamples + 1);          // 내부 점만
const FVector Point = Lerp(From, To, Alpha) + Z(StandChestHeightCm);
RouteRisk = 보이는 표본 수 / 표본 수;
```

**두 끝은 세지 않는다.** 양 끝은 *비교 대상인 두 자리 자체*이고 이미 각자 값이 매겨져
있다 — 이 항이 재는 것은 **그 사이를 건너는 일**이다.

**표본 높이는 서 있는 가슴 높이로 고정이다. 그것이 실제로 건너는 방식이기 때문이다.**
기어가는 값으로 매기면 **모든 회랑이 안전해 보인다** — 그리고 병사는 그 안전한 회랑을
서서 뛰어 건넌다.

`RouteRiskWeight` 가 1보다 크면 **"건너는 동안 보이느니 나쁜 자리에 남겠다"** 가 된다.
건너는 거리가 길고 보는 쪽이 쏘고 있을 때 맞는 본능이다.

> ⚠ **표본은 직선 위에 있다. 네브메시 경로가 아니다.** 건물을 돌아가는 경로는 **틀리게
> 평가된다** — 실제로는 건물이 가려 주는데 직선은 뚫린 것으로 읽는다(또는 그 반대).
> 이 항이 잡으려고 들어온 **탁 트인 회랑**은 직선과 경로가 같은 경우이므로 그 자리에서는
> 맞는다. → **[W20]**

### 2.3 땅의 값

`Objective != nullptr` 일 때만 값이 있다. 없으면 **이 항은 0이고 2절은 두 항짜리로 돈다**
(6절 — 지금이 그 상태다).

### 2.4 건너는 값은 결정에 물린다

```
BestCost + MoveImprovementMargin < HereCost      → 그때만 움직인다
```

`MoveImprovementMargin 0.25`. **여유가 없으면 거의 같은 두 자리 사이를 영원히 오간다.**
"움직이는 것 자체의 값"을 결정 쪽에 물리는 장치이고, 그것은 **실제로 값이다.**

## 3. `ASoldierObjective` — 로직이 없는 레벨 마커 [A]

```
OwningFaction    ESoldierFaction      이 땅을 쥔 쪽
RadiusCm         900                  여기까지는 "쥐고 있는" 것으로 친다
DefendBandCm     900                  반경 밖에서 비용이 1까지 오르는 폭
ApproachScaleCm  6000                 공격측 거리 비용의 정규화 길이
```

액터가 하는 일은 **자기를 그리는 것뿐**이다. 점수는 **필요한 쪽이 당겨 간다.**

### 3.1 ★ 한 액터가 **양쪽**을 섬긴다

```cpp
Faction == OwningFaction ? Defend : Attack        // Neutral 이면 None
```

**쥔 쪽은 지키고 나머지 전부가 뺏는다.** 그래서 **마커 하나가 수비수와 공격수를 동시에
만든다** — "공격 목표 액터"와 "방어 목표 액터"를 따로 놓을 필요가 없고, 놓는 사람이
**둘을 어긋나게 놓을 방법도 없다.**

### 3.2 ★ 수비는 **평평한 0 구간**이다 — 거리 비용이 아니라 (P73)

```
DistanceCm <= RadiusCm            → 0            (평평하다)
그 밖                              → clamp((Distance − Radius) / DefendBand, 0, 1)
```

**반경 안에서는 위치 비용이 정확히 0이다.** 그래야 수비수가 **엄폐와 사계만 보고**
자기 사격 위치를 고른다.

거리로 매기면 — **수비대가 중심점 한 곳으로 붕괴한다.** 그리고 그 점은 대개
**싸우기에 가장 나쁜 자리**다(사방이 트인 한가운데). **한 점을 향한 거리 비용은 최적해를
그 점으로 끌어당긴다** — 지켜야 할 것이 *점*이 아니라 *구역*이면 비용도 구역이어야 한다.

`DefendBandCm` 은 **"더 나은 사격 위치를 찾아 얼마나 멀리까지 나갈 것인가"** 를 정한다 —
밴드가 끝나기 전에 엄폐가 당기는 힘보다 땅이 당기는 힘이 커지는 지점이 답이다.

### 3.3 공격은 **평지도 고원도 없다**

```
clamp(DistanceCm / ApproachScaleCm, 0, 1)
```

**한 뼘 가까워지는 것이 언제나 값이 있다.** 공격측에게 "이만큼 왔으면 됐다"는 거리는
존재하지 않으므로 평탄 구간을 두지 않았다. `ApproachScaleCm` 은 문턱이 아니라 **미터를
노출과 같은 통화로 바꾸는 환율**이다.

### 3.4 높이는 안 센다

```cpp
const FVector Delta = Foot - GetActorLocation();
DistanceCm = FVector(Delta.X, Delta.Y, 0).Size();       // 수평만
```

**목표 바로 위 옥상은 바닥과 똑같이 "그 위"다.** 높이를 세면 **수비수가 높은 자리에서
밀려난다** — 그 자리가 대개 지키기 가장 좋은 자리인데.

## 4. ★ 나오는 그림 — **측면기동은 *남는 것*이다** [B]

아무 데도 "측면으로 돌아라"라고 쓰여 있지 않다. 다음이 전부 **같은 점수식 하나**에서 나온다.

```
거리가 비용이다              →  공격측이 전진한다
전진하면 제압당한다           →  자세가 내려간다
자세가 내려가면 노출의 값이    →  거리의 값에 비해 커진다
   상대적으로 커진다
남는 가장 싼 접근            →  보이지 않는 쪽
```

**정면 경로가 비싸지고 남은 것이 측면일 뿐이다.** 상태도 없고 "flank" 라는 이름의 코드도
없다.

> **[B] — 기구는 코드로 확인했고 산술도 성립하지만, 이 거동을 플레이에서 본 적이 없다.**
> 6절대로 **레벨에 목표가 한 개도 놓여 있지 않아** 지금은 셋째 항이 항상 0이다. → **[C-88]**

## 5. 예산과 결선 [A]

```
SamplesPerCandidate = HeightSamples(3) + RouteSamples(3) = 6
MaxTracesPerTick    = 6                         → 틱당 후보 1개, 한 바퀴 12틱
```

경로 표본이 들어오면서 **후보 한 개의 값이 3발에서 6발로 올랐고 예산도 4→6으로 올랐다**
(값의 이력은 `..._engagement_and_cover.md` 8절 표가 옛 값을 갖고 있다).

**지금 서 있는 자리는 예산 밖에서 매 틱 평가된다** — 그 답만은 *지금* 필요하기 때문이다
(자세를 정한다). 그래서 **병사당 트레이스는 최대 3(여기) + 6(후보) = 9발/틱**이다.
45명이면 틱당 405발이 상한이고, **재 본 적이 없다** → **[C-83]**.

몇 가지가 이 층의 성격을 정한다.

| 사실 | 왜 |
|---|---|
| **위협이 없어도 돈다** | 땅의 값은 **총알 없이도 있다.** 교전 시작 전에 수비수를 자기 자리로, 공격수를 앞으로 보내는 것이 이것이다 |
| 위협이 없으면 `Exposure`·`RequiredStance` 는 **0** | 숨을 대상이 없는 병사는 **노출된 것이 아니라 그냥 밖에 있는 것**이다. 웅크릴 이유가 없다 |
| **진행 중인 이동은 안 건드린다** | `..._engagement_and_cover.md` 7.4절 |
| 목표는 `BeginPlay` 에서 **가장 가까운 것 하나**로 고정 | 목표는 움직이지 않는 레벨 가구라는 전제다. ⚠ **국면에 따라 목표가 바뀌는 일이 불가능하다** → **[W25]** |

## 6. ⚠ 지금 이 층은 **잠들어 있다** — 레벨에 목표가 **0개** [A]

```
L_SoldierTest.umap 의 이름 테이블에 "SoldierObjective" 가 없다.
(레벨 저장 2026-09-13 18:27 · 클래스 작성 19:12 — 클래스가 레벨보다 늦다)
```

`USoldierCoverComponent::BeginPlay` 의 `TActorIterator<ASoldierObjective>` 가 아무것도
못 찾으므로 `Objective == nullptr` → **셋째 항이 항상 0**이다.

**즉 지금 실제로 도는 것은 노출 + 경로 두 항이고, 1절이 말한 "무모함"은 아직 그대로다.**
목표 액터를 레벨에 놓기 전까지 이 문서의 3·4절은 **코드로만 존재한다.** → **[W25]**

> 이것을 적어 두는 이유: **클래스가 있다는 것과 그것이 도는 것은 다른 사실**이고,
> 다음 세션이 "목표 층이 들어갔다"는 머리글만 보고 **원인을 다른 데서 찾을 수 있다.**

## 8. 디버그 [A]

```
SoldierLab.Debug.Objective 1    목표 원(반경) + 옅은 원(반경+밴드) + 기둥
                                아군 소유 = 파랑 / 적 소유 = 주황
SoldierLab.Debug.Cover 1        후보 구체 + 몸 표본 트레이스 + 경로 표본 점
                                텍스트 "exp .. obj .. cost .. stance ..  moving"
```

**목표 오버레이는 `SoldierLab.Debug.AI.Filter` / `.Self` 를 따르지 않는다.**
그 둘은 *병사*를 고르는 필터이고 목표는 병사가 아니다 — 한 개가 세계에 하나 그려진다.

> ⚠ [B] 경로 표본 점은 **막힘 = 어두운 초록 / 보임 = 붉은색**으로 그린다. P70 규약에서
> **초록은 "눈으로 본 앎"의 색**이므로 두 오버레이를 같이 켜면 **한 번 더 겹칠 수 있다.**
> 지금 읽히는지는 확인하지 않았다.

## 9. ⚠ 컴파일 함정 — `AActor` 안에서 지역변수를 `Role` 이라 짓지 말 것 (P75) [A]

```cpp
⛔  const ESoldierObjectiveRole Role = GetRoleFor(Faction);        // C4458
✅  const ESoldierObjectiveRole ObjectiveRole = GetRoleFor(Faction);
```

`AActor::Role`(네트워크 역할)을 가린다. **도메인에서 자연스러운 이름일수록 엔진 베이스
클래스가 이미 쓰고 있을 확률이 높다** — `Role` · `Owner` · `Instigator` · `Tags` 가 전부
그렇다. 코드에는 **왜 이름이 저렇게 길어졌는지** 주석으로 남겼다.
