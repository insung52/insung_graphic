### 3.1 모디파이어 목록 순서 규약

Animation Data Modifiers 목록 순서는 **"Apply All Modifiers"의 실행 순서**다. 개별 Apply는
순서와 무관하지만, 목록이 틀려 있으면 **나중에 Apply All을 누르는 순간 조용히 망가진다.**

**강제되는 제약 2개:**
- `AM_EncodeRootBone`이 **[7][8][9]보다 먼저** — 셋 다 루트모션을 읽는다
- `AM_FootSteps_Walk_Soldier`가 **`AM_BakePhaseCurve...`보다 먼저** — 노티파이 의존

## 4. PSD 설정 (GASP 기준 승계)

```
Schema           : PSS_Default                          ← CMC 경로. GASP 것을 그대로, 새로 만들지 말 것
NormalizationSet : PSN_Dense_All                        ← 없으면 GASP DB와 비용 기준이 어긋난다
PreviewMesh      : SKM_UEFN_Mannequin
PoseSearchMode   : PCAKDTree · PCA 4 · leaf 16 · neighbors 200   (GASP와 동일)
```

> **정정 (2026-09-04)**: 처음에는 `PSS_Relaxed_Loops` / `PSN_Relaxed_All`로 만들었다.
> [C-40]에서 그 조합이 **Mover 경로**의 것임이 밝혀져 [Q11]에서 CMC를 확정하며 위 값으로 바꿨다.
> 아래 `Curve_Phase` 관측은 **전환 전** 수치다 — `PSS_Default`에는 커브 채널이 아예 없다
> (`2026-09-04_c34_clip_curve_mapping.md` 3.2절).

> **UE5.8에는 "Build Index" 버튼이 없다** (2026-09-08 확인). 인덱싱은 **자동·비동기**로,
> 에셋 로드·변경 때마다 `FAsyncPoseSearchDatabasesManagement::RequestAsyncBuildIndex`가 건다.
> **확인은 로그로 한다** — MCP `LogsToolset.GetLogEntries(category="LogPoseSearch")`:
>
> ```
> <hash> - PSD_이름 BeginCache
> <hash> - PSD_이름 BuildIndex Succeeded      ← 이게 마지막 줄이면 성공
> <hash> - PSD_이름 BuildIndex stored to DDC
> ```
>
> 클립을 하나씩 넣으면 그때마다 재인덱싱이 돌고 이전 것은 `Cancelled`로 찍힌다 — 정상이다.
> `Warning: Database None entry N has no associated animation asset`는 **행만 만들고 클립을
> 아직 안 넣은 중간 상태**의 경고다. 최종 빌드에 남아 있으면 빈 행이 있다는 뜻이다.

인덱싱 후 `Data Details`에서 채널이 값을 읽는지 확인한다:

```
Traj          weight 0.873    ← 궤적이 매칭의 주축
Curve_Phase   weight 0.044    ← (PSS_Relaxed_Loops 시절) Phase 커브를 읽고 있다는 증거였다
HeadX_pelvis  weight 0.039
```

> **GASP 기존 PSD에 우리 클립을 넣지 말 것.** 견착 클립이 비무장 DB에 섞이면 MM이
> 상황에 안 맞게 뽑아 쓰고 GASP 원본이 오염된다(`CLAUDE.md` P2).

## 5. ★ 재사용할 수 없는 것 — 리빌드가 필요한 자작 모듈
