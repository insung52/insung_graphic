## ★ 이 문서를 읽는 사람 — 문체 규칙 (먼저 읽을 것)

**이 표는 개발자용이 아니다. 상위 부서에 개발팀 현황을 보여주는 용도다.**

`titan/` 폴더의 devlog 는 개발팀이 서로 보기 위해 쓴 것이라 클래스명·엔진 내부 동작·버그 수정
이력이 그대로 적혀 있다. **그 문장을 그대로 옮기면 읽는 사람은 무슨 말인지 모른다.** 그래서
`실제구현내용` 열은 devlog 를 읽고 **문맥을 파악한 뒤 핵심 개념만 추려 다시 쓴다.**

| 쓴다 | 쓰지 않는다 |
|---|---|
| 무엇을 할 수 있게 됐는가 | 클래스·변수·파일·함수·콘솔변수 이름 |
| 왜 그렇게 했는가(개념 수준) | 버그 수정 나열, 엔진 내부 구현 설명 |
| 성과가 드러나는 수치(지연 0.45→0.07초, 2.3→31fps) | 값 튜닝 내역, 검증 상태(→ `비고` 열 몫) |
| 시스템·기능 단위의 작업 | 단순 버그 수정 1건, 내부 조사 기록, 개발 도구 내부 사정 |

**행을 만들 기준도 같다.** 단순한 버그 수정이나 외부 사람이 몰라도 되는 내용은 **행 자체를 만들지
않는다**(2026-09-29 기준). 버그 수정이 어떤 기능의 일부라면 그 기능 행 본문에 결과만 한 줄로
녹이고, 단독 버그·내부 조사만 있는 행은 지운다. `비고` 열에도 내부 추적번호(`[C-163]` 등),
클래스·콘솔변수 이름, 세션 간 인수인계 메모를 쓰지 않는다.

예 — 개인 판단 AI 의 위험도 계산을 이렇게 쓴다:

> 주변을 격자로 나누고 적이 있을 만한 곳에서 조명을 비추는 방식으로 위험도를 계산한다.
> 적 시선이 닿는 곳은 밝고 엄폐물 뒤는 그림자가 지므로, '엄폐물 뒤가 안전하다'가 별도 규칙 없이
> 계산만으로 나온다.

## 이 폴더가 원본인 이유

기존 방식은 xlsx 파일 자체가 원본이라 (1) 엑셀로 열어두면 다른 쪽이 쓰기를 못 하고 (2) 고칠 때마다
구글드라이브에 다시 올려야 했다. 그래서 2026-09-18부터 **TSV 텍스트 파일을 원본**으로 두고,
xlsx/구글시트는 필요할 때 여기서 밀어내는 산출물로 바꿨다.

- 사람은 **VS Code로 연다** (엑셀로 열면 잠긴다). 읽기 편하게 보려면 확장 Rainbow CSV(칸 색·정렬)
  또는 Edit CSV(격자 편집) 사용.
- Claude 세션은 Edit 툴로 행 단위로 고친다. 파일이 바뀐 걸 감지하면 툴이 거부하므로 사람의
  수정을 덮어쓰지 못한다.
- 규칙 하나: **고치면 바로 저장.** 미저장 상태에서 다른 쪽이 쓰면 VS Code가 충돌 경고를 띄운다
  → Compare로 합치면 됨.
- 셀 안에 탭·개행 금지(TSV 구조가 깨짐). 긴 문장은 그냥 한 줄로 쓴다.
- 인코딩 UTF-8(BOM 없음). 엑셀에 직접 import할 일이 있으면 import 시 인코딩을 UTF-8로 고를 것.

### 시트 → TSV 역반영 절차

시트에서 고친 뒤 파일 ▸ 다운로드 ▸ TSV로 받아 Claude에게 경로를 주면, 헤더 이름 기준으로 diff해서
바뀐 셀만 골라 반영하고 문서와 대조한다(제목 블록·Gantt 열은 자동으로 무시). 상태를 바꾼 행은
근거 문서를 다시 읽어 본문에 근거를 덧붙이므로 시트 문구와 TSV 문구가 같지 않을 수 있다 — TSV가 원본.

## 상태 구분 (`현재상태` / `상태` 열)

| 상태 | 의미 |
|---|---|
| 완료 | 구현 완료. 실동작 또는 실측으로 확인됨. |
| 완료(구현방식 확정) | 구현 완료. 단, 기존 WBS의 표현과 실제 구현 방식이 다름 — 이후 확정된 방식을 내용에 적었음. |
| 진행중 | 진행 중이거나, 코드는 완료했으나 검증이 남은 항목. |
| 미착수 | 아직 착수하지 않음. |
| 보류(상위체계 미확정) | 상위체계(지휘통제 시스템) 관련 정보를 전달받지 못해 진행할 수 없는 항목. `3_상위체계_미확정.tsv` 참고. |
| 보류(일시중단) | 시작했다가 멈춘 병행 트랙. 폐기 아님(현재 Genesis 1건). |
| 폐기/불필요 | 현재 방향과 맞지 않거나 요구사항에 없어 진행하지 않는 항목. **행을 지우지 않고 남긴다.** |

`4_잔여과제.tsv`의 `구분` 열은 별도 축이다: **★ 패키징 전 필수** / 검증 대기(즉시 가능) /
검증 대기(현장 조건 필요) / 구현 대기 / 구현 대기(SoldierLab) / 성능/품질 / 정리 / 대외 / 미해결 버그.
- **★ 패키징 전 필수** — 이걸 안 하고 패키징하면 납품물이 깨진다. 최우선.
- **검증 대기(즉시 가능)** — 우리 환경(Tailscale/사내망 2대 PC, 로컬 리눅스·윈도우, Extreme 3D Pro)에서
  지금 진행할 수 있는 것.
- **검증 대기(현장 조건 필요)** — 시연 장비·네트워크가 정해져야 가능한 것.

## 판정 원칙

- **기존 행은 하나도 삭제하지 않는다.** 지금 방향과 맞지 않는 항목은 `폐기/불필요`로 표시하고
  사유를 적는다.
- **표현 차이는 "구현 방식이 이렇게 확정됐다"로 쓴다.** 기존 WBS는 상세설계서를 기준으로 미리
  작성된 것이라 실제 구현과 다른 항목이 많다. "기획서가 틀렸다"가 아니라 "이후 이렇게 확정됨"으로.
- **일정은 실제 작업 시기로 적는다.** 기존 일정 기간(2026-05-11 ~ 07-31)은 경과했고 새 기준일이
  없어서, 계획 날짜 대신 devlog에 기록된 실제 작업 시기를 `시작일`/`완료일`에 쓴다. 5~7월 초기
  작업은 devlog가 없어 월 단위 근사. Gantt는 이 두 열로 구글시트에서 그린다(실적 Gantt이지 계획
  Gantt가 아님).
- **근거는 `titan/`의 개발 문서(devlog)만.** `memo.md`는 최신화되지 않는 개인 스크래치 노트라
  근거로 쓰지 않는다 — 다른 문서가 `memo.md`에서 옮겨온 항목도 마찬가지(원 devlog까지 확인).
- **devlog 문장을 그대로 옮기지 않는다.** 읽는 사람이 개발자가 아니므로 문맥을 파악한 뒤 핵심
  개념만 추려 다시 쓴다(맨 위 문체 규칙).
- **요구사항에 없어도 우리가 필요해서 만든 것은 완료로 잡는다.** 원본 WBS 행이 '요구사항 미확정'
  으로 남아 있는데 실제로는 다른 방식으로 만들어 쓰고 있는 경우가 있다 — 신규 행만 추가하고
  원본 행을 미착수로 두면 같은 기능이 두 곳에서 반대로 표시된다(2026-09-28 정정 2건).
