# 드론 위치보고 전문 (K05.1) 정리

2026-11-04 / 설계단계 / `기동플랫폼_위치보고전문형식.xlsx`(비번 titan)의 K05.1 전문 필드 정의와 자체방호 드론 값 매핑 초안. 경로·주기·일부 필드는 LIG 답변 대기.

> 성격: **드론 한 대의 현재 상태를 주기적으로 알리는 메시지.** 객체탐지 결과(JSON 문서)와는 별개.
> 원본 시트: `K05.1(위치보고)` 1장, 상위 키 `UnitPositionList[]`(배열).
> **아래 "매핑(제안)" 열은 내 초안**이고 엑셀에 있는 내용이 아니다.

---

## 1. 전문 구조

```
K05.1
 └ UnitPositionList[]            ← 배열 (드론 1대면 원소 1개)
     ├ unitReferenceNumber
     ├ latitude / longitude
     ├ locationSource / locationQuality
     ├ course / speedKph / altitudeFeet
     ├ year / month / day / hour / minute / second
     └ aerialType / maritimeType / subsurfaceType / groundType
```

- 모든 필드 타입이 **String**.
- 시트 오른쪽에 참고 정보: 대분류/중분류/소분류/객체/장비명 = `여단본부 / 본부중대 / - / FPV / FPV01`, 코드 예 `KIB01 / HHC02 / 00000 / 00000 / FPV01`.
- 같은 시트의 "FPV 정찰드론 재원정보"(리모아이 002B): 전폭 1.8m · 전장 1.44m · 이륙중량 3.4kg · 최대속도 80km · 운용반경 10km. (부대 정보용 참고치. 우리 드론 물리와 일치시켜야 하는 요구인지는 불명)

## 2. 필드 정의

| 필드 | 설명 | 타입 | 엑셀 비고 | 매핑(제안) | 상태 |
|---|---|---|---|---|---|
| `unitReferenceNumber` | 부대참조번호(아군부대정보코드) | String | 예시 `KIB01-HHC01-00000-00000-FPV01` | 설정값(고정 문자열) | 예시 중 `HHC01`/`HHC02` 불일치 — 확인 |
| `latitude` | 부대위치(위도) | String | `1~16777215 \| +90/16777215 ~ +90 도` | 드론 월드 위치 → 위경도(`GeoCoordinateUtils`) → 정수 인코딩 | 인코딩 해석 확인 |
| `longitude` | 부대위치(경도) | String | `1~33554431 \| +180/33554431 ~ +180 도` | 위와 동일 | 인코딩 해석 확인 |
| `locationSource` | 위치 출처 | String | "미식별" | ? | **값 미정** |

### 위·경도 인코딩 (해석 — 확정 아님)

- 위도 `1~16777215` = 2^24−1, 경도 `1~33554431` = 2^25−1.
- 읽는 법 후보: `정수 = round(도 / 90 × 16777215)` (위도), `round(도 / 180 × 33554431)` (경도).
  비고의 "+90/16777215 ~ +90 도"는 해상도(1 LSB = 90/16777215°)를 뜻하는 것으로 읽힘.
- 우리 지역(약 위도 37.9°, 경도 128.2°)은 둘 다 양수라 부호 문제는 없음. 그래도 부호 표현(음수 허용 여부)은 확인.
- 예: 위도 37.8870258 → 약 7,062,000대, 경도 128.2434063 → 약 23,907,000대 (후보식 기준).

## 3. 자세(roll/pitch/yaw)가 없다

- 메일은 "실시간 **위치, 자세** 정보를 위치보고전문형식 참고해서 출력"이라고 했으나 전문에 자세 필드가 없고 방향은 `course`뿐.
- 자세는 객체탐지 JSON의 `sourceOrientation`에 들어 있음. K05.1에 자세가 더 필요한지는 LIG 확인 항목.

## 4. 우리 쪽 데이터 출처 (구현 시 참고)

| 값 | 출처 |
|---|---|
| 드론 월드 위치/속도/yaw | `ADronePawn` (Chaos 강체) — `vehicle/drone/drone_flight_dev_guide.md` |
| 월드→위경도 | `GeoCoordinateUtils.h` (랜드스케이프 코너 2점 보정, `guide/real2world.md`) |
| 상태 패널 값 | `UStatusHUDComponent` (배터리·비행시간 등 — 이 전문에는 해당 필드 없음) |
| 통신 채널 | UGV와 동일한 UDP+JSON 계열 후보 — 경로 LIG 확인 |

- 멀티플레이: 드론 시뮬 주체가 서버/클라이언트 중 어디인지(모드별 다름)에 따라 송신 위치가 달라짐 — 가이드 15.2절 규약 확인.
- 시나리오 재시작 시 드론이 `ResetTo`로 원위치 복귀 → 보고 값이 순간 이동으로 보일 수 있음(허용 여부 확인).

## 5. LIG 확인 필요 (요약)

1. 송신 경로(IP/포트/프로토콜), 송신 주기
2. JSON 키 그대로 `{"UnitPositionList":[{...}]}` 형태로 보내는지, 외부 래퍼(`cmd`/`src`/`recv`)가 필요한지
3. `locationSource`/`locationQuality`/`aerialType` 등 값
4. 위·경도 정수 인코딩 해석, 부호 처리
5. 시각 기준(시나리오/실시간, 시간대), 고도 기준(해발/지면)
6. 자세 필드 필요 여부

## 6. 구현 방침 (제안)

- 메시지 생성(직렬화)과 전송을 분리, IP/포트/주기는 설정값.
- 값이 "미식별"인 필드는 LIG 지정 전까지 `"미식별"` 문자열로 채움(공란 아님).
