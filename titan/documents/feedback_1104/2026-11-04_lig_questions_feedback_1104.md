## A. LIG에 물어볼 것

### A-1. 드론 위치보고 (K05.1, 기동플랫폼_위치보고전문형식.xlsx)

0. **수신 쪽 사양 (드론 위치보고·BoundingBox JSON 공통, 가장 먼저)**: 우리 자체방호 에뮬레이터는 우리가 만든 통제기 UI(WBP)로 드론/RCWS를 직접 조작하는 프로그램이고, 상위체계 프로토콜은 받은 적이 없다
   (2026-08-06 답변: 자체방호통제기→상위체계 ICD 미정). 이번 요청의 데이터는 **우리 프로그램에서 누구에게, 어떤 방식으로 보내야 하는가?**
   상위체계(또는 LIG 수신 프로그램)의 수신 IP / 포트 / 프로토콜, 메시지 래퍼(`cmd/src/recv/data` 봉투 등) 필요 여부를 달라.
   (ICD 시트 1의 IP/포트는 UGV 에뮬레이터↔UGV 통제기 구간이라 자체방호에는 해당하지 않음.)
1. **어느 경로로 보내는가?** IP / 포트 / 프로토콜. (위 0번 답에 따름. 기본안 없음 — 경로 가정 없이 구현하고 설정값으로 둠)
2. **송신 주기**는? (정해진 값 없음 — 임시 1Hz)
3. **위치보고에 자세(roll/pitch/yaw)가 필요한가?** 엑셀 포맷에는 자세 필드가 없고 `course`(동/서/남/북 문자열)만 있음. 메일의 "위치, 자세 정보"가 무슨 뜻인지 확인.
4. **값이 비어 있는 필드를 어떻게 채우는가?** `locationSource`, `locationQuality`, `aerialType`, `maritimeType`, `subsurfaceType`, `groundType` ("미식별"/공란).
5. `unitReferenceNumber`에 넣을 값. 예시 `KIB01-HHC01-00000-00000-FPV01`을 그대로 쓰는지, 자체방호 드론용 코드가 따로 있는지.
6. `latitude` / `longitude` 인코딩이 `1~16777215|+90/16777215` 식의 정수 인코딩인데, **문자열로 정수를 보내는 것이 맞는지**(음수/남반구·서경 처리 포함). 북한 접경 위도라 음수는 안 쓰이겠지만 규칙 확인.
7. `year`~`second` 기준 시각: 시나리오 시간인가 실시간(UTC/KST)인가.
8. `altitudeFeet`는 피트 단위가 맞는지, `speedKph`는 km/h 정수인지 소수인지.

### A-2. 드론 영상 / 객체탐지 BoundingBox (sample1_boxed_metadata.json)

1. **JSON을 실시간으로 프레임마다 보내는가, 영상 1개당 파일로 만들어 주는가?** 샘플은 `frames[]` 240개짜리 파일 형태.
2. 실시간이면 **어느 경로**로 보내는가? (UDP / TCP / RTSP 메타데이터 / 기타 — A-1의 0번 구성 확인에 따름) 프레임 단위로 보낼 때 `{ "frames": [ 한 개 ] }` 형태가 맞는지.
3. **클래스 체계**: 샘플은 `targetClassId = 1`, 라벨 `"T-72A 전차"` 하나뿐. 우리가 구분하는 객체(적 병사, 아군 병사, 트럭, UGV, 드론 등)에 대한 `targetClassId` 표와 라벨 문자열을 정해줄 수 있는가?
4. **탐지 대상 범위**: 어떤 객체를 박스로 내보내야 하는가(적군만? 아군도?).
5. `targetBoundingBox`의 `x, y, width, height` **좌표 기준**: 영상 해상도 대비 픽셀인가, 정규화인가? 샘플 값 범위상 픽셀로 보임(x 최대 835, y 최대 457). 기준 해상도는?
6. `scenarioTime`의 기준 시각과 `frameIndex` 시작점(재시작 시 0으로 돌아가는지).
7. 드론 영상 RTSP **URL / 해상도 / fps**의 기대 사양(현재 구현 사양과 맞는지 확인용).
8. 필드 `location.altitude`, `targetLocation.altitude`는 **해발**인가 지면 기준인가? (샘플은 680m 상공 → 지상 480m로 보임: 해발로 추정)

### A-3. UGV ICD 1104 반영

1. **`Runtime`**(총 실행시간, `HH-MM-SS`): **시나리오 재시작 시 0으로 초기화되어야 하는가**, 에뮬레이터 프로세스 기동 시각부터 계속 누적인가?
2. **`Azimuth` / `Elevation` / `TotalBullet`** 의 정의:
   - `Azimuth` 0~360의 기준: 차체 전방 기준(상대)인가 진북 기준(절대)인가?
   - `Elevation` 0~180이고 "-90로 보정해서 사용예정": 90이 수평인가? (-90 보정 시 -90~+90) 정확히 어떤 값을 넣으면 되는가?
   - `TotalBullet`: **현재 잔탄**인가 최대 탄수(MAX 200)인가?
3. **`ObjectClass` 메모("값을 기존 classified")**: 정확히 어떤 요청인가? 현재 우리는 ICD의 `Human`/`Car`에 더해 6분류(ugv/uav/truck/ally/enemy 등)로 보내고 있음(`protocol/2026-09-02_object_class_expansion.md`). 이것을 `Human`/`Car` 두 값으로 되돌리라는 것인가, 그대로 두는 것이 맞는가?
4. **객체 인식 결과 박스 위치 어긋남**("영상에 보이는 타겟 위치와 box 위치 차이가 심함"):
   - 어느 카메라(EO/IR)와 어느 상황(줌 배율, 이동 중/정지)에서 얼마나 어긋나는가? 가능하면 **캡처 화면 1~2장**.
   - LIG 쪽이 영상 크기로 환산에 쓰는 해상도(가로/세로)는 얼마인가? (좌표는 65535 스케일링이라 해상도 가정이 다르면 어긋남)
5. **`SelectCameraButton` 메모("IR 카메라 흑백 마스킹")**: 지금 IR 영상이 초록색인데 **흑백(그레이스케일)으로 바꾸라는 뜻**인가? 화이트핫/블랙핫 구분이 필요한가?
6. **`Steering` 좌/우 조향 감도**: 어느 정도로 낮추라는 요청인가(정량 기준이 있는가)? 현재 어떤 문제(너무 민감해서 휙휙 돈다 등)가 있었는가?
7. 오타 정정 키: `ControlRight`, `Battery`, `Letter` 외에 **추가 오타 목록**이 있는가? ("keys 부분 오타 몇개" 라고만 되어 있음)

### A-4. 카메라 / UI

1. **[자기방호] 이동형 지휘소 쿼터뷰 자리에 드론 영상 패널을 배치**하는 변경에서, 이동형 지휘소 CCTV 영상은 **더 이상 필요 없는가**(화면 표시만 빼고 RTSP 송출은 유지?), 아니면 어디서든 계속 볼 수 있어야 하는가?
2. RCWS 카메라 시점 "실제보다 뒤쪽": 실제 장비의 **RCWS 카메라 위치 기준 치수**(차체 전방 기준 몇 cm 앞인지) 자료가 있는가?
3. UGV 주행 카메라(전/후/좌/우) 높이: **목표 높이**(지상고 또는 현재 대비 +몇 cm) 기준이 있는가?

### A-5. 시나리오 초기화 / RCWS

1. "초기화까지 걸리는 시간 확인": **어느 구간**의 시간을 알고 싶은가? (재시작 버튼 입력 → 화면이 처음 상태로 돌아올 때까지? 원격통제기 연결 재설정까지 포함?) 허용 기준(몇 초 이내)이 있는가?
2. **[UGV] RCWS 상/하 각도 제한**: 몇 도~몇 도를 원하는가? 현재 조이스틱 조작에는 -20°~60° 제한이 있음. **UDP(원격통제기) 조작 시 제한이 없어 보였던 구체 상황**(어떤 명령, 어느 값)을 알려줄 수 있는가?
3. **탄 소진 시 자동 재장전**: 재장전 지연 시간(우리 제안 1~2초)과 재장전 후 탄수(최대 200발?)가 맞는가?

### A-6. 조이스틱 제어 (자기방호)

1. "**H2 스틱**"이 `velocityone_tester`의 `joystick_reader.py` 기준에서 어느 축/장치를 가리키는가? (우리 쪽 장비 매핑 확인용)
2. "조이스틱 메인 스틱으로 **UGV 카메라** 제어": 자기방호축에서 UGV 카메라를 직접 제어한다는 뜻인가, **드론 짐벌 카메라**의 오기인가? (현재는 메인 스틱이 드론 비행 또는 짐벌)
3. 현재 H2 스틱/메인 스틱 입력에 대한 **LIG 쪽 기대 동작표**가 있는가? (없으면 `joystick_reader.py`의 축 이름과 값 범위를 기준으로 매핑)

## B. 내부에서 먼저 확인할 것 (LIG에 묻지 않아도 되는 것)

- 드론에 이미 `URtspStreamComponent`가 붙어 있음(`DronePawn.cpp`) → **현재 드론 RTSP가 실제로 나가는지 / 사양**을 코드와 실측으로 확인.
- RCWS 각도 제한 `MinElevationDegrees(-20)` / `MaxElevationDegrees(60)`이 있음 → **UDP 경로(원격통제기 직접 각도 지정)가 이 clamp를 우회하는지** 코드 확인.
- 시나리오 재시작은 레벨 리로드가 아닌 **제자리 리셋** → 로그 타임스탬프로 입력~`RunLocalRestartEnd` 구간 측정.
- 객체 인식 박스 어긋남: 캡처 해상도 vs 박스 계산 해상도 vs RTSP 인코드 지연을 우리 쪽에서 먼저 재현·확인 (우리 `ugv controller demo`에서는 심하지 않았다는 점을 근거로 LIG 환경과 차이를 좁힌다).
- ICD 오타 수정(`ConrtrolRight`→`ControlRight`, `Batterry`→`Battery`, `Latter`→`Letter`)은 확정 사항 → 코드 `UGVRemoteControlSubsystem.cpp:833,836,128` 대응.
- `value`의 string→int(`"20"`→`20`)는 LIG가 **현상태(Int) 유지**로 확정 → 수정 없음.
