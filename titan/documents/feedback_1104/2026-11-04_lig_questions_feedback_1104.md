## A. LIG에 물어볼 것

### 드론 데이터 출력 (위치보고 K05.1 · BoundingBox JSON)

**Q1. 두 데이터를 어디로, 어떤 방식으로 보내야 하나요?**
받는 쪽(상위체계 / LIG 수신 프로그램), 프로토콜(UDP·TCP 등), 메시지 외곽 형식(UGV ICD처럼 `cmd/src/recv/data`로 감싸는지, 본문 JSON만 보내는지)을 알려주세요.
- 배경: 자기방호→상위체계 ICD는 받은 적이 없음(2026-08-06 답변 "미정"). UGV ICD의 IP/포트는 UGV 구간 전용.
- 수신 IP/포트는 기존 RTSP·UDP·리플리케이션처럼 **로비(축 선택) 화면에서 입력**받게 할 것이라 따로 묻지 않음.
- 기본안: UDP + UTF-8 JSON, 외곽 형식 없이 본문만.

**Q2. 두 데이터의 송신 주기는 얼마인가요?**
- K05.1 위치보고: 기본안 1Hz.
- BoundingBox JSON: 프레임마다 실시간으로 보내는지(샘플은 약 24fps, 240프레임을 담은 파일), 일정 주기로 보내는지. 기본안: 실시간, 영상 프레임 1장당 메시지 1개(`{"frames":[프레임 1개]}`).

### UGV ICD 1104

**Q3. `Runtime`은 시나리오 재시작 때 0으로 초기화해야 하나요?**
- 기본안: 에뮬레이터 프로세스 기동부터 누적, 재시작해도 유지.

**Q4. `SelectCameraButton` 메모 "IR 카메라 흑백 마스킹"은 어떤 뜻인가요?**
지금 녹색인 IR 영상을 흑백으로 바꾸라는 뜻인지, 사람·차량만 밝게 강조하는 열상 효과를 원하시는지 확인 부탁드립니다.
- 기본안: 흑백(녹색 틴트 제거), UGV·트럭 공통.

### UI

**Q5. 쿼터뷰 자리에 드론 영상 패널을 넣은 뒤, 이동형 지휘소 CCTV 영상은 어떻게 되나요?** (email.md 1번 UI 수정, 사용자 TODO)
화면에서 빠지는 이동형 지휘소 CCTV(쿼터뷰) 영상이 더 이상 필요 없는지, 화면 표시만 빼고 RTSP 송출은 계속 해야 하는지.
- 왜: 필요 없으면 해당 씬캡쳐 렌더링을 끌 수 있고(자기방호 PC 부하 감소), RTSP로 계속 써야 하면 화면에 안 보여도 렌더링·송출을 유지해야 함.
- 기본안: 화면 표시만 빼고 RTSP 송출은 유지.

## B. 이렇게 이해했습니다 (확인 요청)

1. **`TotalBullet`(MAX 200발)** → "현재 잔탄 수를 보내고, RCWS 최대 탄수를 200발로 맞추라"는 뜻으로 이해했습니다. 이에 따라 UGV·이동형 지휘소 RCWS 최대 탄수를 기존 600발에서 200발로 변경하고, 탄 소진 시 자동 재장전도 200발 기준으로 적용합니다.
2. **"조이스틱의 메인 스틱으로 UGV 카메라 제어"** → "메인 스틱으로 자기방호 드론 카메라 제어"로 이해했습니다(자기방호 쪽에는 UGV 카메라를 조작하는 기능이 없고, UGV는 UGV 통제기에서만 조작). 따라서 H2 미니스틱 = 이동형 지휘소 RCWS, 메인 스틱 = 드론 카메라로 매핑합니다.

## C. 회신에 같이 넣을 "이렇게 진행하겠습니다" (질문 아님)

**시나리오 초기화 시간** (메일 3번 회신)

| 구간 | 시간 |
|---|---|
| 적 전멸 → 재시작 확인창 표시 | 5초 |
| (자동 재시작일 때) 카운트다운 | 10초 |
| 재시작 버튼 → 화면 원상복귀 | 약 1.2초 (실측 657회 중앙값 1.24초, 페이드 0.8초 포함) |
| 화면 복귀 → 시나리오 자동 시작 | 3초 |

통제기 UDP 연결과 RTSP는 재시작 중에도 끊기지 않음. 5·10·3초는 설정값이라 요청 시 줄일 수 있음.

**UGV ICD 1104**
- 키 오타 3건(`ControlRight`/`Battery`/`Letter`) 수정, `value` Int 현상 유지.
- `UGV_RCWS_Status`: `Azimuth`는 현재 UGV·트럭 RCWS가 쓰는 방위 기준(진북 0°, 시계방향) 그대로, `Elevation`은 ICD 문구대로 고각+90(0~180), `TotalBullet`은 현재 잔탄.
- `Runtime`: `HH-MM-SS`(Q3 답에 따라 초기화 여부 결정).
- 객체 탐지 `ObjectClass`: 현행 분류값 유지.
- 조향 감도는 낮추고 조절값으로 열어둠.
- 탄 소진 시 약 1.5초 뒤 잔탄만 자동 보충(애니메이션·입력 없음).
- RCWS 객체인식 박스 어긋남: 우리 쪽에서 원인 파악 후 수정본으로 재확인 요청.

**드론 데이터 형식**
- 박스 좌표: 샘플 역산 결과 기준 해상도 1024×576 → 드론 RTSP도 1024×576으로 맞추고 픽셀은 그 기준.
- 박스는 **그 프레임 영상에 실제로 보이는 대상만** 포함.
- 분류(`targetClassId`·라벨): 기존 UGV 객체 탐지와 같은 분류 체계 사용.
- `sourceOrientation` = 카메라 시선 방향(샘플과 동일), 고도 = 해발(실제 지형 고도 자료 기준으로 계산).
- K05.1: 엑셀 정의 그대로 — 위경도 정수 인코딩, `course` 8방위, `altitudeFeet` 해발, `speedKph` km/h, 시각은 실시간(KST). 고도·속도는 소수점 둘째 자리까지. "미식별" 필드는 "미식별", 나머지 공란, `unitReferenceNumber`는 엑셀 예시값.
- 자세 정보는 K05.1에 필드가 없으므로 BoundingBox JSON의 `sourceOrientation`으로 제공.
- 드론 RTSP는 이미 송출 중: `rtsp://<자기방호PC>:8554/selfdefense/uav_gimbal`.

## E. 분석본 정정 메모 (같은 폴더의 다른 `2026-11-04_*.md`)

1. "ICD 엑셀은 세션이 읽을 수 없음" → 비번 titan으로 복호화해 직접 읽힘.
2. `ObjectClass` 메모는 시트2 H44(자율주행 탐색 결과)에만 있음. "시트 2·3" 아님.
3. 각도 제한은 조이스틱 경로만이 아니라 UDP 포함 모든 경로에 차체 기준으로 적용됨. 단 상태값 `ElevationDegrees`는 수평 기준이라, 이 값+90을 보내면 경사면에서 70~150을 벗어날 수 있음(0~180 범위 안이라 ICD 위반은 아님).
4. 최대 탄수는 UGV·트럭 모두 600(1200은 발사속도 rpm).
5. 드론 JSON 문서의 "x 최대 835, y 최대 457"은 x+w, y+h의 최대값. 기준 해상도는 역산하면 1024×576.
6. K05.1 문서의 위경도 예시(37.8870258, 128.2434063)는 LIG 샘플 드론 위치이며 우리 맵 밖.
7. 현재 드론 HUD 고도는 이륙점 기준이라 해발도 지면도 아님.
8. `guide/joystick_camera_control_dev_guide.md` §3.4 "Axis 번호 1부터" → 0부터.
